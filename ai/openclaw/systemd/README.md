# systemd units for OpenClaw

System-wide units (in `/etc/systemd/system/`) that drive the OpenClaw
dashboard, monitoring, and per-agent project-resource lifecycle. All
units are host-portable; deploy via `../install.sh`.

| Unit | Type | Purpose | Required everywhere? |
|---|---|---|---|
| `agent-dashboard.service` | simple | Node server on `127.0.0.1:3013` serving `/agents.html` + `/agents/events` SSE + `/agents/registry.json` | Yes |
| `ai-monitor.service` | oneshot | AI judgment layer over `openclaw-integrity-check` — triages incidents, wakes/restarts agents, sends Telegram alerts via the monitor agent | Yes |
| `ai-monitor.timer` | timer | Runs the AI monitor 2 min after the previous tick completes | Yes |
| `openclaw-integrity.service` | oneshot | Runs `openclaw-integrity-check` (validates registry, services, listeners, Gmail watches) | Yes |
| `openclaw-integrity.timer` | timer | Runs the integrity check every 2 min | Yes |
| `openclaw-backup.service` | oneshot | Daily root-only backup of small critical OpenClaw state to `/var/backups/openclaw` | Yes |
| `openclaw-backup.timer` | timer | Daily 04:20 (±20 min) trigger for the above | Yes |
| `openclaw-doc-sync.service` | oneshot | Reconciles PM-managed files: copies agent docs from the active checkout and canonical `openclaw.json` files into each agent's home as regular `0600` runtime files. Content-diff gated. | Yes |
| `openclaw-doc-sync.timer` | timer | Runs full file reconciliation every 5 min as a fallback | Yes |
| `openclaw-config-sync.service` | oneshot | Runs config-only reconciliation immediately after a PM-owned canonical config changes | Yes |
| `openclaw-config-sync.path` | path | Watches every `/srv/agents/openclaw/<user>/openclaw.json`. **Host-specific** — generated by `install.sh` from `agents.json` | Yes (generated per host) |
| `openclaw-typing-keepalive.service` | simple | Telegram typing-indicator sidecar for `claude-cli` provider (non-streaming → openclaw's built-in keepalive lapses mid-turn) | Anywhere agents use claude-cli |
| `openclaw-monitor-sync.service` | oneshot | Reconciles per-agent `~/.local/openclaw/monitor.json` against actual systemd state — enabled resources are `enable --now`, disabled are `stop` | Yes |
| `openclaw-monitor-sync.timer` | timer | Periodic drift correction every 5 min for the above | Yes |
| `openclaw-monitor-sync.path` | path | Watches every per-agent `monitor.json`; fires sync within ~1 s of any edit. **Host-specific** — generated by `install.sh` from `agents.json` | Yes (generated per host) |
| `gmail-watch-renew.service` | oneshot | Re-runs `gmail-watch.js` for every agent with `integrations.gmail: true` | Anywhere there's a Gmail-integrated agent |
| `gmail-watch-renew.timer` | timer | Daily 04:00 (±10 min) trigger for the above | Same as service |

## Host-specific generation

`openclaw-monitor-sync.path.in` and `openclaw-config-sync.path.in` ship as
templates with a placeholder `@PATH_CHANGED_LINES@`. `install.sh` reads
`/etc/openclaw/agents.json` and emits one monitor-state path and one canonical
config path per enabled agent before installing the concrete `.path` units.
systemd Path units don't accept globs, hence the per-host enumeration.

## Why these aren't part of the OpenClaw npm package

Cleaner separation: OpenClaw is the per-agent runtime gateway. Everything
in this `systemd/` directory is host-level orchestration that ai-monitor
and the dashboard rely on. Shipping these in the shared knowledge repo
keeps them in lockstep with the bin/ scripts they depend on.

`ai-monitor.service` has a twelve-minute outer timeout because one bounded tick
can include external probes, every configured AI fallback timeout, a
180-second monitor-agent decision window, and recovery confirmation. The timer
uses `OnUnitInactiveSec`, so a slow tick cannot create overlapping or
immediate back-to-back monitor runs.

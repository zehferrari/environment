## Runtime Layout

- **Unified Environment Repository**: `/srv/Code/environment` (working tree checkouts are in `/srv/Code/environment.worktrees/...`).
- **Shared OpenClaw Docs and Skills**: [/srv/Code/environment/ai/openclaw](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw).
- **Repository Access**: All agent accounts belong to the `code-agents` group and access code files under the `/srv/Code` directory.
- **Shared-Tree Permissions**: `/srv/Code` is group-owned by `code-agents`, group-writable with **setgid + default ACLs**, so any code-agent (including the monitor agent) can build any worktree — not just whoever created `node_modules`. Enforced/repaired by the idempotent `/usr/local/sbin/code-tree-perms` (source: `ai/openclaw/bin/code-tree-perms`, installed by `install.sh`).
- **Runtime Secrets (monitor-owned)**: The PM webapp's live secrets/data are owned by the monitor-agent user and locked away from the coding agents — `ai/web/.env.local` (`600 monitor-agent`) and the SQLite DB dir `ai/web/prisma/prisma/` (`0700 monitor-agent`, which also protects its `-wal`/`-shm`). The surrounding source tree stays group-collaborative.
- **Agent Registry**: [/etc/openclaw/agents.json](file:///etc/openclaw/agents.json), which symlinks to [/srv/agents/index.json](file:///srv/agents/index.json) (the live registry file kept outside of git).
- **Dashboard Configuration**: [/etc/agent-dashboard/config.json](file:///etc/agent-dashboard/config.json).
- **Dashboard Source Files and Nginx Web Root**: [/srv/Code/environment/ai/web](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/web).
- **Nginx Web Server**: Serves [agents.html](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/web/agents.html) directly from the environment repo checkout.
- **Agent Workspaces**:
  - `coding-agent`: `/home/<coding-agent>/workspace`
  - `monitor-agent`: `/home/<monitor-agent>/.openclaw/workspace` (no user-facing standard workspace)
- **Shared Documents Symlinks**: The shared documents ([AGENTS.md](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw/AGENTS.md), [ROLES.md](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw/ROLES.md), [TEAM_WORKFLOW.md](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw/TEAM_WORKFLOW.md), [CODE_REPOS.md](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw/CODE_REPOS.md), [USER.md](file:///srv/Code/environment.worktrees/feature_HOMELAB-41-local-project-manager-webapp-/ai/openclaw/USER.md)) are symlinked from the shared knowledge directory to both `~/workspace/` and `~/.openclaw/workspace/` for the coding agents. For the monitor agent, they are symlinked only to `~/.openclaw/workspace/`.
- **Per-Agent Files**: Per-agent files (`SOUL.md`, `IDENTITY.md`, `TOOLS.md`, `MEMORY.md`, `HEARTBEAT.md`) live canonically in `~/workspace/<file>` with a symlink in `~/.openclaw/workspace/<file>` pointing to it.
- **Agent State Directories**: `/home/{<coding-agent>,<monitor-agent>}/.openclaw`.

## Gmail and Google Watchers

Host `x1` uses Google Workspace/Gmail watchers rather than local Maildir. Gmail polling runs per coding agent to preserve security isolation and prevent mailbox confusion:

- **Listener Service**: `openclaw-gmail-listener.service` is enabled for each coding agent user.
- **Pub/Sub Subscriptions**:
  - per coding agent: `gmail-inbox-watch-<coding-agent>-sub`
- **Shared Topic**: Both subscriptions attach to the shared GCP Pub/Sub topic `projects/<gcp-project>/topics/gmail-inbox-watch`.
- **Ingestion & Wake**:
  - The push listener script (`gmail-push-worker.js`) fetches messages when notified, writes events to `~/.openclaw/mail/events.jsonl`, marks the email as read immediately, and wakes the agent via:
    ```bash
    sudo -n /usr/local/sbin/openclaw-control wake-agent <self>
    ```
- **Sudoers**: `/etc/sudoers.d/openclaw-mail-self-wake` gives coding agents permissions to run only their own `wake-agent` commands without a password.

## Models and Providers

As of May 2026, host `x1` relies dynamically on **OpenAI OAuth**, **Claude CLI**, and **Ollama** (running locally on `x1` and bridging `:cloud` models to `https://ollama.com` for the agents) to provision the models in use. Model configurations and fallback paths are managed dynamically per-user in each agent's private `~/.openclaw/openclaw.json` configuration file rather than being hardcoded in central host documentation.

- **Ollama endpoint**: each agent's `models.providers.ollama.baseUrl` points at `http://127.0.0.1:11434` — the local Ollama on `x1` (managed by `ollama.service`, `OLLAMA_HOST=0.0.0.0:11434`). The previous `http://ollama.local` indirection through `moonlight` is **deprecated** — moonlight's nginx upstream pointed at `10.0.0.17` (a different LAN host) which doesn't actually serve the agents' `:cloud` models, so requests were either silently mis-routed or going to x1's local Ollama anyway. Agents now hit the local instance directly.
- **Local Fallback Model**: `qwen2.5:3b-instruct` (~2 GB q4_K_M) is installed locally on the `x1` CPU as a last-resort offline fallback.

## Jira and Webhooks

Jira routing uses a central monitor-owned webhook dispatcher:

- **Receivers**: `/home/<monitor-agent>/webhooks/jira-receiver.js` (port `3014`) and `/home/<monitor-agent>/webhooks/bitbucket-receiver.js` (port `3015`), running under the monitor-agent user.
- **Routing Rules**: Derived from `/srv/agents/index.json` via `/etc/openclaw/agents.json`. Webhooks route only to enabled coding agents with the matching integration enabled, using `jira_account_id` for Jira @-mentions.
- **Wake Action**: Incoming events queue a task inside `/home/<user>/tasks/current.md` and trigger a wake via:
  ```bash
  sudo /usr/local/sbin/openclaw-control wake-agent <agent-user>
  ```
- **Sudoers**: `/etc/sudoers.d/<monitor-agent>-openclaw-control` allows the monitor-agent user to execute `openclaw-control` commands (`restart-services`, `wake-agent`, `restart-and-wake`) for target coding agents.
- **Pending Mention Queue**: `/var/lib/ai-monitor/pending-mentions/` tracks unresolved mentions that are periodically audited by `ai-monitor`.
